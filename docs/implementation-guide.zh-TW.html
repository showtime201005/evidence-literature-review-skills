01目標與目前狀態

交接入口：完整進度交接 · 套件說明 · 可攜現況證據 JSON · 下載交接 ZIP（GitHub 檔案頁請選 raw 下載）。

目標是從提供的 100 篇、每篇約 10 頁論文開始，於 90 分鐘內完成主報告、100 張精簡證據卡、比較表，以及能回到原文的完整追溯資料。

研究限於使用者提供的語料。系統不自動搜尋外部學術資料庫、不補造作者／年份／DOI，也不將「這批文本沒有提到」推成「整個領域不存在」。目前完整 native 入口接受 Markdown，沒有 PDF 解析入口。

目前是可執行的實驗系統，還不是已驗收的百篇研究服務。

最新兩篇冷測在卡片階段耗盡共享修訂預算而失敗；六案例局部控制雖命中預期結果，不能證明全流程或百篇品質。離線 SDK 測試通過，僅證明對應程式路徑與機械契約可運作。

每次執行必須保留

  • 完整來源閱讀與重要漏項查核。
  • 主張由自己的引用支持，限定與否定不反轉。
  • 重要負向、無效、缺失量測與失敗案例。
  • 跨論文新推論的獨立審查。
  • 真正 task 身份、來源版本、失敗原稿與交付雜湊。

驗收不能混為一談

  • 可安裝：檔案、依賴與入口可載入。
  • 機械完整：來源、映射、責任、版本與身份匹配。
  • 模型判斷：審查模型逐項給出科學結論。
  • 品質驗收：對照已知缺陷與人工審查。
  • 時間驗收：真正冷啟動至完整交付在時限內。

03真實代理、TaskStore 與分層責任

身份由 runtime 產生，不讓模型自己宣告

主代理必須實際呼叫 DeepAgents SDK 的 task 工具，才建立 worker。身份含獨立 context、parent context、task tool-call、實際 skill 快照及輸入／輸出 hash。TaskStore 以 lease 管理 pending／running／accepted／failed；coordinator 取回短 receipt，再由 host 核對任務與 artifact。

Writer 與 reviewer 使用不同任務上下文；reviewer 不能以 writer 自我辯護替代原文判斷。它們仍可能使用同一 Qwen 模型，因此這是執行身份與上下文獨立，不代表模型錯誤完全互相獨立。匯出的 identity JSON 僅是 provenance 紀錄，不是可重新匯入的信任 registry，也不是數位簽章。

v1 與 v2 的責任轉移

v1 將來源與整合分成不同 proof／assembly 任務。v2 改讓一位獨立 paper reviewer 同時看全文、reader、卡片與連續 render，承擔 source support、raw retention、全文漏項與整合責任；每個 section reviewer 同理審新推論與該層整合。host 只檢查版本、映射、覆蓋、依賴與交付，不冒充語意審稿者。這是新契約與負載取捨，尚不能宣稱品質等同或優於 v1。

04五項 skills：用途、input／output／protocol

四個 leaf skills 可各自安裝使用；完整 literature-review 才需要五個 skills。assembly-auditor 是 v1 runtime role，映射至 verify-citations，不是第六個 skill。下表的 schema 名稱是實際介面，並非任意自然語言檔名。

Skill目的與 native role主要 input主要 output／邊界
analyze-paper全文逐 part 分析；readerscientific-source/1：原始 UTF-8 bytes 的完整 parts、來源 hash、研究問題。scientific-record/1：九欄 findings、evidence、逐 part observations、問題判定、重要義務。結構接受尚未科學批准。
compare-papers比較條件、差異、反證與缺口；comparerreview-draft-packet/1，kind=comparison；v2 由合格卡片建立 direct-premise packet。review-section/1，含 paper×dimension cells、claims、展開 retention。不是獨立審查結論。
write-review精簡卡片與分層綜合；writerkind=paper_card 或 synthesis 的 draft packet；精確 source refs／actual premises／retention obligations。mapped section 與連續 render。卡片最多 12 claims、合計 3000 Unicode 字元；不得用限額刪重要反證。
verify-citations獨立支持、限定、引用與遺漏審查；verifier單任務 CLI：native-proof-input/1。完整 v2：paper／section bundles，及可選 closed packets。matching proof 或 v2 attestation，保留 negative／unresolved。單節點結果不能批准整份報告。
literature-review協調全文到交付；coordinator新 Markdown 目錄＋問題 JSON；完整 native run 不以舊 analysis cache 冒充 cold。主報告、全篇卡片、比較表、引用與原文、完整 audit；未通過則保存 unpublished attempt。

analyze-paper：從原文到可查核記錄

scientific-source/1 → scientific-record/1

使用 source_packet(paper_id, raw_bytes, questions) 建封包。它按空白行保留完整文字及 byte offsets；重組必須等於原檔。Reader 對每個 part 交具體 observation，不能只交「已讀」。

九欄為 research_question、contributions、method、evaluation、results、limitations、conditions、relevance、unexpected_findings。每個 finding 有 attribution、來源 evidence 及適用的 retention tags；欄位的 extracted／not_reported／not_applicable／unresolved 不可互相代用。

submit_result({"data": {
  "observations": [...],   // 每個 part 一項
  "findings": [...],       // local_id、field、text、attribution、evidence、obligations
  "fields": [...],         // 九欄完整判定
  "questions": [...]       // status、reason、support、counterevidence
}})

這是形狀說明，含註解與省略號，不能直接當合法 JSON。quote=null 表示 host 綁完整原 part，不是沒交原文。字串／多餘 keys 不會被新 raw reader 入口悄悄轉正。

compare-papers／write-review：寫作與 lineage

review-draft-packet/1 → review-section/1

葉節點用 draft_packet(...)；上層用 inference_packet(...) 或 v2 的 section_draft_packet_v2(...)。上層保留完整 direct-premise prose 與來源版本，並不重新傳送全部原始論文；原文查核責任必須存在於 child closure。

data.claims[] = local_id, text, evidence_refs, question_ids,
                attribution, scope, population_paper_ids, premise_claim_ids
data.retention_groups[] = obligation_ids, status(included|excluded), claim_ids, reason
data.cells[] = paper_id, dimension, claim_ids

模型使用短 obligation aliases 及可逆 grouped retention；host 展開後，每個原 obligation 都有自己的 disposition。reader_evidence_ids 是讀者抽取 bookkeeping；寫作引用必須用 paper_id/part_id，例如 paper01/p0007。Comparison 必須覆蓋指定 paper×dimension，不可把異質 metric 當成同一排行榜。

verify-citations：四種明確責任

source proof／paper／section／closed
  1. v1 source proof：從原始 packets、records、sections 重建計畫，只允許指定的 dependency-free source 節點獨立執行。
  2. v2 paper reviewer：完整 source＋reader＋card＋render，查主張、逐原始義務、全文漏項、render 整合。
  3. v2 section reviewer：完整 direct premises＋target，查每個新推論、premise retention、族群／問題／cells／整合。
  4. 附加 closed checks：一個 claim 只看自己的 refs；retention 只看 finding、自己的原文及實際 named destinations，不能跨引用救援。

後三種由完整 v2 workflow 使用 Python API 調度；目前沒有 native_task --role paper-reviewer 或獨立 closed-check 正式 CLI。Legacy 人類報告查核入口也不等於上述單節點 native verifier。

05Windows 與 Ubuntu 22.04 設置

使用 Python 3.11+ 的獨立虛擬環境。Ubuntu 22.04 預設 Python 3.10 不符合要求，先由組織認可方式備妥相容 Python；下例的 python3.11 必須已存在。安裝依賴、下載 tokenizer 會連網；安裝器與 doctor 本身不呼叫模型。

& .\.venv\Scripts\python.exe -m pip install -r skills/literature-review/scripts/requirements-native.txt

# 選擇一個全新的研究專案目錄

# 安全地在目前程序設定 key；不將真值寫進檔案
$apiSecret = Read-Host "OpenRouter API key" -AsSecureString
$env:OPENROUTER_API_KEY = [System.Net.NetworkCredential]::new("", $apiSecret).Password

Ubuntu 22.04／Bash

# 在 repository 根目錄；python3.11 已備妥
python3.11 -m venv .venv

Installer 已統一為一份實作

根目錄 scripts/install_skills.py 與 bundled skills/literature-review/scripts/install_skills.py 現在都載入 stdlib-only 的 skill_installation.py。舊盤點 §11「兩份實作不一致」描述的是已修正的狀態。

  • DeepAgents profile 為 deepagents-native-typed/1：選取 skill 的 SKILL／references，搭配 canonical native runtime、doctor、task、pins 與 installer；literature-review 額外有 full review／reading 入口。
  • 來源安裝包仍須提供 canonical literature-review scripts。安裝後單一 leaf skill 可獨立執行，不必安裝其他四項；它帶自己的 installer，但重新安裝仍需符合 canonical source-package 規則。

  • native-installation.json 保存來源檔案 hash 與 model_inference=not_tested。native profile 排除 legacy harness／深層示例 assets；不能假設已安裝 native leaf 同時帶有舊 CLI。
  • codex、claude-code、opencode 分支仍採完整 selected-skill copy；相同旗標不代表它們已完成同等 native 模型驗收。

平台可攜性須分別看檔案／安裝／SDK 離線測試與真模型冷測。Windows 或 Ubuntu 任一 scripted 測試通過，不能自動證明另一平台的百篇時限與品質。可攜 Ubuntu 22.04 紀錄：reader prompt overlay、selectors／安裝 overlay、closed checks／安裝 overlay、closed schema 補充。每份只涵蓋其 captured bytes 與列明 suites；共享 installer 等後續修正不自動納入舊 overlay。

06獨立任務與完整流程：真實命令

下面的 native_task／native_review 命令會真正呼叫模型並計費。

命令是依目前入口核對的語法範本，並非本文件新執行的成功紀錄。先備妥合法 input packet；不要把任意 Markdown 或省略號 JSON 直接當 native_task input。所有 output 目錄都應全新，且位於來源目錄之外。

6.1 只安裝並診斷一個 skill

python -X utf8 /ABS/REPO/scripts/install_skills.py --source /ABS/REPO/skills --target /ABS/PROJECT --harness deepagents --skill analyze-paper

python -X utf8 /ABS/PROJECT/skills/analyze-paper/scripts/native_doctor.py --skills-root /ABS/PROJECT/skills --tokenizer /ABS/PROJECT/qwen-tokenizer.json --skill analyze-paper

將 skill 名換成 write-review、compare-papers 或 verify-citations 即可安裝該角色。完整流程則不加 --skill，安裝五項。單任務的 coordinator 也使用所選 skill，而非強制依賴 literature-review 已安裝。

6.2 analyze-paper：一份完整原文封包

reader-source.json 必須由 scientific_records.source_packet(...) 形成。以下為可放進呼叫端 Python 的公開 builder 用法；它不呼叫模型：

import json, sys
from pathlib import Path
sys.path.insert(0, "/ABS/PROJECT/skills/analyze-paper/scripts/runtime")
from litreview_core.scientific_records import source_packet

questions = json.loads(Path("/ABS/questions.json").read_text(encoding="utf-8"))
if isinstance(questions, dict):
    questions = questions["questions"]
packet = source_packet("paper01", Path("/ABS/papers/paper01.md").read_bytes(), questions)
Path("/ABS/reader-source.json").write_text(
    json.dumps(packet, ensure_ascii=False, indent=2), encoding="utf-8")
python -X utf8 /ABS/PROJECT/skills/analyze-paper/scripts/native_task.py --role reader --input /ABS/reader-source.json --out /ABS/reader-run-new --skills-root /ABS/PROJECT/skills --tokenizer /ABS/PROJECT/qwen-tokenizer.json --deadline 300 --max-model-calls 3 --reasoning low --tool-choice forced

接受後的 artifact.json 是 scientific record；task-result.json 是單任務執行報告，不是完整 review 驗收。

6.3 write-review：卡片或 synthesis

writer-packet.json 是 kind=paper_card 或 synthesis 的 review-draft-packet/1。例如一張卡片可由 draft_packet('paper_card', [source], [record], questions, include_reader_findings=True) 建立；來源與 record 必須匹配。Synthesis 使用 actual direct premises，不是把先前對話記憶當輸入。

python -X utf8 /ABS/PROJECT/skills/write-review/scripts/native_task.py --role writer --input /ABS/writer-packet.json --out /ABS/writer-run-new --skills-root /ABS/PROJECT/skills --tokenizer /ABS/PROJECT/qwen-tokenizer.json --deadline 300 --max-model-calls 3 --reasoning low --tool-choice forced

6.4 compare-papers：指定維度的比較

comparison-packet.json 的 kind 必須為 comparison，包含指定 papers、dimensions、義務與可追溯材料。公開 builder 為 draft_packet(...) 或 inference_packet(sections, packets, records, questions, kind='comparison', dimensions=...)。後者只接受每篇唯一的 paper-card premises。v2 完整流程另要求 qualified child closure。

python -X utf8 /ABS/PROJECT/skills/compare-papers/scripts/native_task.py --role comparer --input /ABS/comparison-packet.json --out /ABS/comparison-run-new --skills-root /ABS/PROJECT/skills --tokenizer /ABS/PROJECT/qwen-tokenizer.json --deadline 300 --max-model-calls 3 --reasoning low --tool-choice forced

6.5 verify-citations：目前單任務 native source 節點

proof-input.json 必須正好含以下五個 keys；陣列內是實際 objects，不能交自製可信身份或外部 proof。Node ID 必須由相同設定下的 plan_review(sections, packets, records, ...) 重建得到，且 kind=source、role=verifier、dependencies=[]。

{
  "schema": "native-proof-input/1",
  "packets": [...],
  "records": [...],
  "sections": [...],
  "node_id": "由重建計畫取得的來源節點 ID"
}
python -X utf8 /ABS/PROJECT/skills/verify-citations/scripts/native_task.py --role verifier --input /ABS/proof-input.json --out /ABS/proof-run-new --skills-root /ABS/PROJECT/skills --tokenizer /ABS/PROJECT/qwen-tokenizer.json --deadline 300 --max-model-calls 3 --reasoning low --tool-choice forced --proof-max-units 16

產物含 proof-result.json。它只代表被指派 source responsibility；無法以此替完整報告、所有卡片或任意人類稿件自動批准。--quote-witness 是另外的 v1 實驗，不是 v2 whole-unit selector 的別名。

6.6 literature-review：完整 experimental v2

papers 第一層放 1–100 個 .md／.markdown；不遞迴，檔名 stem 不得重複或僅大小寫不同。問題檔接受 JSON array 或 {"questions":[...]}。此命令明確啟用 v2、whole-unit 與附加 closed checks，並保留預設 low reasoning 供實驗；它不是已驗收的正式設定。

python -X utf8 /ABS/PROJECT/skills/literature-review/scripts/native_review.py --sources /ABS/PROJECT/papers --questions /ABS/PROJECT/questions.json --out /ABS/PROJECT/review-run-new --skills-root /ABS/PROJECT/skills --tokenizer /ABS/PROJECT/qwen-tokenizer.json --review-protocol v2 --review-observations whole-unit --closed-checks --workers 8 --active-token-limit 1000000 --group-size 4 --deadline 5400 --reviewer-max-output-tokens 16384 --reader-reasoning low --writer-reasoning low --reviewer-reasoning low

07關鍵實作設計：效率與科學責任一起看

Closed checks 不是把全文審查拿掉

局部核對會刻意隱藏未引用材料，防止「資料夾裡別處有支持」救了不當引用。完整 paper reviewer 仍要看到完整原文、reader、卡片與 render，查重要遺漏及整合；section reviewer 仍要看實際 direct premises、retention、cells 與 scope。Closed checks 必須先合格，才允許 full review／下游依賴。

工具 schema 依 packet 限定 unit IDs、minimum IDs、material selector enums 及精確 unit row 數，減少模型把解釋句填進 observation ID 或重複 unit。模型仍須逐 minimum unit 做獨立關係判斷。簡短理由建議以 ID＋有區辨力的支持／缺口說明，不應重抄整段 finding；省 token 不等於已證明判斷品質相同。

新增 strict supported-subset 候選 Python API only

目前 create_model(..., strict_tool_mode='off') 預設不變。候選 strict-supported-subset/1 只對 submit_result function 設 strict:true，只允許明確 Cerebras、allow_fallbacks:false；其他工具不啟用 strict。Named tool choice 保留，leaf parallel tool calls 關閉。

from litreview_core.qwen_transport import create_model
from litreview_core.request_governor import RequestGovernor, ThroughputConfig

governor = RequestGovernor(ThroughputConfig())
model = create_model(
    force_submit=True,
    governor=governor,
    provider_preferences={"only": ["cerebras"], "allow_fallbacks": False},
    strict_tool_mode="strict-supported-subset/1",
)

投影只在 JSON Schema AST 的關鍵字位置移除 Cerebras 不支援的安全 leaf validation constraints，例如 minLength／maxLength、pattern、minItems／maxItems、uniqueItems；所有科學 properties、enums、required 保留。名為 minLength 的科學欄位不會被刪。無法安全投影的 oneOf／allOf／conditional、未知 keywords，或未關閉的 object 直接拒絕。

Canonical host validation 不變，原／投影 schema SHA 與移除 JSON paths 可稽核。實際 request 使用合法 OpenRouter metadata；完整 paths 另在模型 audit／回覆 metadata。投影後的實際 schema 仍計入完整 request 預算。這個候選已有零 API 測試，尚無 CLI 開關，也沒有本候選的真 provider probe 結果；不能把 constrained schema 候選寫成已改善科學正確性。

Cerebras 官方 schema 子集依據：Structured Outputs、Tool Calling。這些是外部參考連結，文件顯示不依賴它們連線。

08200K 是完整請求上限，並行還有總負載門檻

單請求 reservation
  = 完整 input estimate（system + messages + tools/schema + history + framing）
  + max_tokens（含模型 reasoning 使用的 completion 預算）
  + context margin（預設 8,000）

必須同時符合：全域單請求 200,000、所選 route context/output、active-token-limit。
不符合 → 明確拒絕／要求拆任務或改寫 broad claim；不得截斷原文或歷史。

使用 pinned Qwen tokenizer 做含 framing headroom 的估算；provider 實際 usage 才是計費／回報量。沒有 tokenizer 時 UTF-8 byte 預算刻意保守，不能當成實際 TPM。第二輪修格式仍保留第一輪回覆與錯誤 history，因此首輪 fit 不保證重試 fit。

Loading：workers 不等於同時有效模型數

Governor 共用 global concurrency、active token reservations、deadline；預設 aggregate reservation 1,000,000。若每個 active request 約預留 150,000，僅此限制就約容許六個同時執行；即使 workers=16，也不會因此變成十六路。DAG 就緒任務數、quota、延遲、HTTP 重試、CPU／RAM 與輸出體積還會再限制吞吐。

  • --active-token-limit 可實驗性調整 200,000–6,400,000；單請求 200K 不變。提高總量需要同步觀察資源與限流，不能宣稱免費加速。
  • 未知 RPM／TPM 不自行假設；Python governor 可配置，但目前沒有對應 native CLI flags。事件分開記錄 reserved 與實際 usage；缺 usage 不算零成本。
  • 429／暫時服務錯誤會降低 logical concurrency，成功後緩升。Sync HTTP client 按 thread 重用，async client 按 event loop 重用；pool 不儲存金鑰 headers。
  • HTTP 最多兩次 attempts；重試等待不占 active slot，尊重原 deadline 與 Retry-After。Read timeout 可能已計費，不盲目重試；schema／semantic negative 不屬於傳輸重試。
百篇時間不能由兩篇時間乘以 50 得到。

百篇會改變 ready concurrency、階層數、premise／retention 數、上層 context 與修訂負擔。需要實際 task service-time 分布、quota、reservation 與完整品質結果，才能做有條件容量分析；本指南不提供沒有驗證依據的線性工期承諾。

09修訂、版本失效與已知缺點

1. 每次原始提交先落盤

保留完整 raw arguments、實際身份、錯誤與來源版本。格式不符不得在保存前消失，也不能以格式清理改變科學值。

2. 格式修復有限，真 negative 終止

同一 leaf 有 model-call 上限；短 feedback 指出 locations、types、missing／unknown／duplicate IDs。支持判斷伴隨 missing components 仍不能通過，也不允許當成普通格式錯誤洗掉。

3. Writer 針對失敗版本修訂

同一全流程共用最多兩輪 scientific repair，並共享原 deadline。可修文字、限定、來源與保留映射，但不能替模型自動寫出「正確答案」。舊稿與 negative history 保留。

4. 新版本重新 qualification

Source、card、premise 或 mapping 改變即產生新 hash，使依賴失效。V2 未合格版本不得流向 comparison／synthesis；v1 只有 exact inputs／coverage／deps／runtime identity／closure 不變的原 sealed proof 才能同 run 重用。

目前不能忽略的缺點

可追溯實例：先於 reviewer 結論的 source→card 獨立審查（JSON）與既有 reviewer 對照（JSON）。其中確認六組漏檢，與另三項未確定的精度疑慮分開記錄；不是以任一不確定疑慮冒充已確認錯誤。

  • 共享兩輪預算容易在早期耗盡。它是整個 run 的上限，不是每篇各兩輪；最新兩篇測試已因此停止。需要評估修訂收斂與批次回饋策略，不能以無限重試換表面成功。
  • 完整審查仍會誤判。已發現 own-reference support、named-destination retention、數字／分類／時間／程度限定與 governing negation 的錯誤；可逆編碼或完美 coverage 不能消除它們。
  • 交付語言與密度也是品質。要求繁中、精簡、完整限定；型別正確的英文長稿或過度壓縮卡片都不代表使用者需求已完成。
  • 長輸出與 reasoning 可能吃掉 completion。Low 是請求設定，不是 provider 一定遵守的硬 token 上限；off 的速度結果也不能代替品質對照。
  • 完整 native CLI 尚無 resume。失敗資料有保存，但要繼續處理需明確的版本／信任／重用設計；不可把讀過的 cache 當新 cold run 成果。
  • Universal／absence 要完整 scope。「所有研究」「沒有任何」「每個 subgroup」必須檢視全體實際成員與反例，不能只抽支持摘錄或依搜尋零命中決定。

12後續計畫與實作索引

  1. 先降低可避免的格式成本。隔離 probe strict-supported-subset，確認 Cerebras 路由是否真正按完整投影 schema 解碼；同步量初輪與修格式 history 後的 complete wire，保留 canonical host gate。
  2. 驗證 writer handoff 是否有效。完整 finding context 已提供，但需實測 named retention、關係、限定與原引用支持是否改善；不能只計 schema retry 減少。
  3. 讓卡片修訂收斂。評估同輪批次 issue 收集、穩定 failure feedback 與版本局部重查，維持共享 deadline 和有限預算；先完成兩篇 cold，再逐步擴大到十篇。
  4. 對照局部與全文科學品質。保留正／負控制、own-source、governing negation、分類／數值／時間、named destination、重要反證與 universal scope；任何分組或精簡理由都需品質 A/B，不能先視為等效。
  5. 以真負載決定百篇架構。量各角色 service time、p50／p95、quota、input／output／reasoning、repair、CPU／RAM、有效並行與 active reservations；再安排首次百篇全程測試，不用線性放大猜 SLA。
  6. 完成跨平台與交付驗收。固定來源、runtime、skills、依賴與 tokenizer 版本，在 Windows／Ubuntu 22.04 分別驗安裝、真 SDK、外部 cold clock、四類完整交付及人工抽查。
